Developer documentation · v1

快速开始

用几分钟将你的应用连接到 QxAPI。我们的 API 兼容 OpenAI SDK，因此你可以保留熟悉的调用方式，同时获得统一路由和生产级观测能力。

准备好了吗？

你只需要一个 API Key。请在控制台的「API 密钥」中创建，并妥善保存。

安装 SDK

选择你正在使用的语言，安装官方 SDK。

Python

Terminal
pip install qxapi

JavaScript / TypeScript

Terminal
npm install @qxapi/sdk

认证

所有请求都通过 Bearer Token 认证。将 API Key 放在请求头中。

HTTP
Authorization: Bearer your-api-key

发起第一次请求

下面的示例会通过统一端点调用你配置的模型。

Python
from qxapi import QxAPI

client = QxAPI(api_key="your-api-key")
response = client.chat.completions.create(
    model="your-model",
    messages=[{"role": "user", "content": "Hello, QxAPI"}]
)

API 端点

POST/v1/chat/completions

创建一次聊天补全请求。

参数 类型 必填 说明
model string 是 已接入的模型标识
messages array 是 按顺序排列的消息列表
stream boolean 否 是否启用流式响应

三种请求方式对照

QxAPI 提供三种兼容层。选择方式时，优先保持与你现有 SDK 一致；新项目建议从 OpenAI Responses API 开始，需要 Claude 原生能力时使用 Messages API。

方式端点认证适合场景
Claude Messages/v1/messagesx-api-keyClaude 原生能力、system、content blocks
Chat Completions/v1/chat/completionsBearer已有 OpenAI SDK、快速迁移
Responses API/v1/responsesBearer新项目、工具调用、结构化输出

流式响应

流式响应使用 Server-Sent Events（SSE）返回增量内容。客户端应持续读取事件，直到收到结束事件；不要把每个 chunk 当作完整回答保存。

生产建议

设置连接超时、记录 request id，并在网络中断时按幂等策略重试。流式输出已经发送给用户后，建议从断点或新请求恢复。

生产部署建议

密钥管理

将 API Key 放入服务端环境变量或密钥管理系统，禁止提交到 Git、浏览器代码和日志。按环境创建独立项目密钥，并定期轮换。

超时与重试

为普通请求设置 30–60 秒超时；仅对 429、502、503、504 等临时错误使用指数退避。4xx 参数错误应修正请求后再发送。

可观测性

记录 request id、模型、耗时、状态码和 token 用量。日志中脱敏用户输入、Authorization 和 API Key，避免把完整 prompt 写入公开日志。

错误处理

当请求失败时，QxAPI 会返回标准 HTTP 状态码和可读的错误信息。建议对 429 和 5xx 响应使用指数退避重试。
